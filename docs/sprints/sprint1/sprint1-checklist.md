# Checkliste

## Punkteaufteilung (200 Punkte insgesamt):

50 individuell für Studierende je Sprint Review.
– 15 Punkte: Funktionalität und SW Qualität des Projekts
– 15 Punkte: Anwendung der SE Techniken (Testen, GitHub, Sonar, …).
– 20 Punkte: Anwendung von Methoden der Agilen Entwicklung (regelmäßige Planung und Abstimmung,regelmäßige Mitarbeit, SCRUM-Meetings).

5 mögliche Bonuspunkte
– Verbesserung der Scanner Ergebnisse über das geforderte Mindestmaß hinaus (zum Aufbessern einer positiven Note).

## Erwarteter Stand nach Sprint 1

GitHub Projekte, CI-Pipelines, SonarCloud und Quality Gates sind angelegt.
Die Netzwerkkommunikation funktioniert grundlegend.
Erste Sketches für das App-UI sind erstellt.
Erste Kernkomponenten/-Activities der Spielarchitektur sind implementiert.
Der implementierte Code ist getestet und erfüllt die SonarCloud Quality Gates.
Die in Sprint 1 erledigten Tasks/Stories sind im GitHub Board ersichtlich.
Die für Sprint 2 geplanten Tasks/Stories sind Projektmitgliedern zugeordnet.

Agile Entwicklung

GitHub Board und Issues aktuell halten.
Regelmäßig Code committen und pushen.
Feature Branches verwenden (https://www.atlassian.com/.../feature-branch-workflow).
Commit Conventions verwenden (https://www.conventionalcommits.org/, https://cbea.ms/git-commit/).
main-Branch als protected konfigurieren.
Pull Requests für Merges in den main-Branch verwenden (KEIN Squash Merging, KEIN Rebase Merging).
Was zum Sprint Review nicht in den main-Branch integriert ist, gibt es nicht.
main-Branch muss jederzeit lauffähig sein und Quality Gates erfüllen.
