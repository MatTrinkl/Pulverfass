## Branching-Strategie

– Der main-Branch enthält ausschließlich lauffähigen und getesteten Code.

– Neue Features werden in separaten Feature-Branches entwickelt.

– Änderungen dürfen nur über Pull Requests in den main-Branch integriert werden.

– Jeder Pull Request muss von mindestens zwei Teammitgliedern überprüft und freigegeben werden.

– Vor dem Merge müssen alle automatisierten Checks (z. B. CI, Tests, Quality Gates) erfolgreich sein.
